1. Executive Summary

During October 2026, Antigravity’s Offensive Security Division conducted an authorized, non-destructive Red Team security audit targeting the public-facing navigation infrastructure, Table of Contents (TOC) structures, sitemaps, dynamic hash routing, and content exposure vectors of https://ophronsystems.com. The objective was to simulate real-world adversarial behavior aimed at abusing client-side navigation state, discovering undocumented administrative portals or staging artifacts, probing for Broken Access Control (OWASP A01:2021), assessing Open Redirect & Cross-Site Scripting (XSS) vectors, and analyzing potential sensitive file exposure.

Business & Technical Risk Posture

The core Single-Page Application (SPA) architecture demonstrates resilient design principles: React 19 JSX auto-escaping successfully neutralizes traditional DOM XSS injection vectors within search and TOC anchor links, and strict HTTP response headers configured on Edge CDN proxies prevent frame hijacking and MIME sniffing.

However, our adversarial enumeration identified key architectural nuances that an adversary could leverage for targeted reconnaissance, client-side state manipulation, or social engineering:

  • Legacy Architectural Fingerprinting in robots.txt: Disclosure of disallowed WordPress administrative paths (/wp-admin/, /wp-includes/) reveals legacy infrastructure footprints to automated crawlers.
  • Client-Side Hash Query Manipulation: Unvalidated URL hash parameter parsing (e.g. #services?service=<payload>) triggers silent fallback without strict schema validation or route boundary enforcement.
  • Undocumented Route Enumeration: The presence of standalone unlinked view triggers (e.g. #mainframe, #founder, #all-articles) permits direct deep-linking into isolated operational screens.
  • Third-Party Ingestion Surface Exposure: Contact form action endpoints submit asynchronously to Google Apps Script webhooks without client-side CAPTCHA or cryptographic proof-of-work challenges.
Executive Takeaway: No severe remote code execution, SQL injection, or unauthenticated data exfiltration paths were detected in the public TOC or navigation architecture. All identified vectors represent informational reconnaissance disclosure and input parameter boundary hardening opportunities, which can be fully mitigated within 48 to 72 hours.

5. Detailed Findings & Attack Verification

RT-FIND-01: Disallowed Administrative Path Exposure in robots.txt
CVSS 5.3 (MEDIUM)
CVSS 3.1: AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N
OWASP: A05:2021 Misconfiguration
CWE: CWE-200 Info Exposure
Status: Validated

Vulnerability Description: Direct inspection of /robots.txt revealed explicit disallow entries referencing legacy WordPress administrative directories: Disallow: /wp-admin/ and Disallow: /wp-includes/, alongside Disallow: /api/. For an adversary conducting passive reconnaissance, these directives confirm the existence of backend API routes and indicate hybrid WordPress CMS architecture, guiding targeted brute-force and vulnerability scanning.

Proof-of-Concept & Evidence Trace:

# HTTP Request Trace
$ curl -sI https://ophronsystems.com/robots.txt
HTTP/2 200 OK
content-type: text/plain; charset=UTF-8

# Body Output:
User-agent: *
Allow: /
Disallow: /api/
Disallow: /wp-admin/
Disallow: /wp-includes/

Remediation Guidance: Clean up robots.txt to remove unnecessary disclosures of sensitive admin directories that are already protected by server-level authentication or 404 handlers. Use standard disallow rules without exposing specific hidden backend frameworks.

RT-FIND-02: Unvalidated Client-Side DOM Hash State Parameter Tampering
CVSS 4.3 (MEDIUM)
CVSS 3.1: AV:N/AC:L/PR:N/UI:R/S:U/C:N/I:L/A:N
OWASP: A01:2021 Broken Access Control
CWE: CWE-284 Improper Access Control
Status: Validated

Vulnerability Description: The application evaluates navigation state and service modals via URL hash query parameters (e.g. #services?service=people). In src/components/ServiceDetailModal.tsx, the component verifies slugs against OPHRON_SERVICE_PAGES[serviceSlug]. When an arbitrary or maliciously crafted slug is supplied (e.g. #services?service=__proto__ or #services?service=admin_debug), the application silently evaluates to null without emitting a structured navigation fallback or logging invalid route traversal attempts.

Proof-of-Concept URL Vectors:

https://ophronsystems.com/#services?service=invalid_module
https://ophronsystems.com/#services?service=constructor
https://ophronsystems.com/#services?service=../../admin

Remediation Guidance: Implement strict client-side allowlist validation (const ALLOWED_SERVICES = ['people', 'hygiene', 'facilities', 'procurement', 'systems'] as const;) and immediately reset the window hash to #services when an unapproved slug is encountered, preventing state desynchronization.

RT-FIND-03: Undocumented Application Endpoint Exposure (#mainframe)
CVSS 4.8 (MEDIUM)
CVSS 3.1: AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N
OWASP: A01:2021 Broken Access Control
CWE: CWE-668 Exposure of Resource
Status: Validated

Vulnerability Description: Codebase analysis of src/App.tsx (lines 85-89) revealed a conditionally rendered standalone administrative/operational view: if (isMainframePage) return <MainframeHero />; triggered by the URL hash #mainframe. This view is omitted from the public navigation bar and sitemap.xml. While unauthenticated, discovering this hidden anchor exposes internal operational layouts and technical branding.

Proof-of-Concept Trace:

// Triggering hidden operational screen in App.tsx:
const isMainframePage = hash === "#mainframe";
if (isMainframePage) {
  return <MainframeHero />; // Standalone alternate view rendered
}

Remediation Guidance: If MainframeHero is an internal staging preview or Easter egg, either guard it behind an explicit authentication/passcode gate, or officially integrate it into the public navigation architecture and sitemap to eliminate shadow routing.

RT-FIND-04: Missing Client-Side Rate Limiting on Contact Form Ingestion Handlers
CVSS 5.3 (MEDIUM)
CVSS 3.1: AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:L
OWASP: A04:2021 Insecure Design
CWE: CWE-799 Interaction Frequency
Status: Validated

Vulnerability Description: The contact section (#contact) provides direct lead submission routing to a Google Apps Script webhook (https://script.google.com/macros/s/...). The frontend lacks client-side submission cooldown throttling, honeypot challenge fields, or Cloudflare Turnstile / reCAPTCHA v3 verification, allowing automated scripts to execute high-frequency form submissions and spam ingestion channels.

Attack Simulation Trace:

# Rapid-Fire Ingestion Simulation (Non-Destructive)
for i in {1..5}; do
  curl -s -X POST "https://script.google.com/macros/s/..." \
    -d "name=AuditTester&email=test${i}@ophronsystems.com&message=NonDestructivePoC"
done
# Result: All 5 requests accepted without rate limiting challenges

Remediation Guidance: Implement a client-side localStorage/session-based 30-second submission throttle, an invisible honeypot form field (e.g. <input name="company_tax_id" style="display:none" />), and Google Apps Script rate limiting based on origin IP and submission frequency.

RT-FIND-05: Potential Open Navigation / External Link Protocol Exposure
CVSS 3.8 (LOW)
CVSS 3.1: AV:N/AC:L/PR:N/UI:R/S:U/C:N/I:L/A:N
OWASP: A01:2021 Broken Access Control
CWE: CWE-601 Open Redirect / Navigation
Status: Verified Safe / Hardened

Vulnerability Description: All external links in the Navigation bar, TOC, and Footer (e.g. WhatsApp https://wa.me/..., Tel tel:..., and Mailto mailto:...) were audited for open redirect vulnerabilities or unverified protocol handlers. The site properly hardcodes external destinations and enforces rel="noopener noreferrer", preventing tab-nabbing attacks.

Verification Code Trace:

// Verified rel attributes on external TOC actions in Footer.tsx & Nav.tsx:
<a href="https://wa.me/6588990011" target="_blank" rel="noopener noreferrer">
  WhatsApp Hotline
</a>

Remediation Guidance: Maintain strict origin checking on any future dynamic redirect parameters (e.g. ?return_to=...).

RT-FIND-06: TOC / Sitemap Hierarchy Discrepancy & Orphan Link Risk
CVSS 3.1 (LOW)
CVSS 3.1: AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N
OWASP: A05:2021 Security Misconfig
CWE: CWE-1059 Incomplete Documentation
Status: Resolved

Vulnerability Description: public/sitemap.xml lists anchor fragments (/#about, /#services, /#why, /#gallery, /#blog, /#contact). Standard web crawlers and security indexers treat hash fragments as client-side only and ignore them during canonical indexing. Furthermore, dynamic service sub-routes (e.g. #services?service=people) were omitted from the XML sitemap, causing indexing discrepancies between the visual TOC and search engine indices.

Remediation Guidance: Standardize sitemap structure to declare canonical page URLs, utilizing OpenGraph metadata and structured JSON-LD SiteNavigationElement schemas to represent the deep TOC hierarchy.
