# MASTER EXECUTION PROMPT — COMPLETE WEBSITE DOCUMENTATION & PROFESSIONAL DOCUMENT GENERATION

## 1. ROLE AND RESPONSIBILITY

Act as a Senior Technical Documentation Engineer, Business Analyst, Website Content Auditor, UI/UX Documentation Specialist, and Professional Document Designer.

Your task is to inspect my existing website and its associated project files, understand the complete website from beginning to end, extract all relevant content accurately, organize the information into a logical and professional document, and generate the final documentation in BOTH formats:

1. **Professional PDF document (.pdf)**
2. **Editable Microsoft Word document (.docx)**

The documents must be suitable for submission to my Team Lead (TL), internal company review, project handover, business documentation, and future reference.

This is a complete website documentation assignment. Do not create a superficial summary, a short overview, or a basic report. The final deliverables must contain the complete, relevant website content in the correct sequence, with appropriate headings, subheadings, descriptions, images, branding, spacing, alignment, page structure, and professional formatting.

**Primary objective:** Produce an accurate, comprehensive, visually polished, company-branded document that faithfully represents the existing website.

Do not stop after inspecting the homepage. Do not generate the documents until the entire relevant website has been audited.

## 2. MANDATORY RULES — DO NOT VIOLATE

Follow these rules throughout the entire task.

### Rule 1: Inspect before documenting
- Inspect the existing website and the available source code before writing.
- Identify all pages, routes, navigation items, sections, subsections, features, and relevant content.
- Understand the purpose and relationships between pages.
- Review the available project files, assets, images, logo, configuration, and documentation.
- Never assume that the homepage represents the entire website.

### Rule 2: Preserve factual accuracy
- Use the existing website and verified project files as the source of truth.
- Preserve the original meaning of the content.
- Correct grammar, spelling, punctuation, and sentence structure without changing the intended meaning.
- Professionalize informal wording where appropriate.
- Do not invent features, functionality, business claims, statistics, integrations, workflows, or technical details.
- If something cannot be verified, identify it as unavailable, unverified, or not applicable rather than fabricating information.

### Rule 3: Capture complete relevant content
- Document every relevant page and section.
- Do not skip content simply because a page is long or repetitive.
- Consolidate genuinely duplicated information only when doing so does not remove unique details or alter the original meaning.
- Preserve important descriptions, lists, labels, calls to action, tables, workflows, and feature explanations.
- Include technical details only when they are supported by the source code, existing documentation, or observable behavior.

### Rule 4: Maintain the correct order
- Follow the website's actual navigation hierarchy wherever possible.
- Preserve the order of sections within each page.
- Organize the final document from general information to specific information.
- Use consistent numbering, headings, subheadings, captions, and cross-references.
- Do not randomly rearrange the content.

### Rule 5: Use genuine company branding
- Use the actual company logo and the existing website's brand identity.
- Extract the existing color palette, typography, and visual style from the website or approved assets.
- Do not create a replacement logo or substitute a different company's branding.
- Do not invent official brand colors if they cannot be verified.
- If brand information is incomplete, use the available verified brand elements and a restrained professional layout.

### Rule 6: Generate real deliverables
- Create an actual, valid, editable `.docx` file.
- Create an actual, valid, readable `.pdf` file.
- Do not merely provide Markdown, HTML, a proposed outline, or instructions for creating the documents.
- Do not claim that a document was generated unless the file actually exists and has been checked.
- Both documents must contain the same substantive information and use a consistent design system.

### Rule 7: Validate before completion
- Check the generated files, content, page breaks, typography, images, tables, headers, footers, numbering, and layout.
- Resolve any detected formatting or content issues before final delivery.
- Never treat file creation alone as proof that the task is complete.

- Authentication and authorization mechanisms.
- Deployment environment.
- Available logo files, brand assets, images, icons, fonts, and style files.

Do not assume that every technology is used. Include only verified information.

### 3.2 Build a complete page inventory
Inspect the website navigation and the source code to identify:
- Main pages.
- Nested pages and subsections.
- Landing pages.
- Product or service pages.
- About or company pages.
- Feature pages.
- Dashboard pages.
- Forms and input screens.
- Search and listing screens.
- Detail views.
- User account or profile pages.
- Settings pages.
- Administrative pages.

1. Page name.
2. Route or URL.
3. Parent page.
4. Purpose.
5. Main sections.
6. Key features.
7. Available visual assets.
8. Inspection status.
9. Documentation status.
10. Any unresolved information.

### 3.3 Inspect all routes and page states
- Review every discoverable route.
- Inspect both directly accessible pages and pages reached through navigation.
- Review relevant modal dialogs, dropdowns, tabs, accordions, forms, filters, search controls, and interactive components.
- Test representative user interactions when possible.
- Check responsive behavior on desktop and smaller screens when the environment permits.
- Review authenticated or role-specific pages only when legitimate access is available.
- Identify broken links, inaccessible pages, and missing content.
- Never bypass access controls or attempt to access unauthorized information.

Review relevant project files, including:
- Application entry points.
- Routing configuration.

Do not indiscriminately dump the entire repository into the document. Extract information that explains the actual website, its content, functionality, or verified architecture.

### 3.5 Create an internal completeness checklist
Before writing, establish a checklist of every discovered page and relevant section.

A page must not be marked as documented until:
- Its purpose is recorded.
- Its relevant text has been captured.
- Its headings and subheadings are preserved.
- Its important features are described.
- Its relevant visual content has been considered.
- Its position in the website hierarchy is established.
- Its content has been checked for accuracy.

## 8. PHASE 6 — PROFESSIONAL PAGE DESIGN AND LAYOUT

The document must look like a professionally designed corporate publication, not copied website text pasted into Word.

### 8.1 Page setup
Use:
- A4 portrait orientation as the default.
- Landscape pages only for genuinely wide diagrams or tables.
- Consistent page margins, approximately 20–25 mm where suitable.
- A consistent text area and grid.
- Appropriate paragraph spacing.
- Consistent indentation.
- Balanced whitespace.

Use a different page layout only when it materially improves readability.

### 8.2 Cover page design
Create a premium, restrained corporate cover featuring:
- Company logo.
- Document title.
- Website or project name.
- A subtle brand-colored design element.
- Optional verified website screenshot or visual.
- Version and preparation date.

The cover must be visually balanced, aligned, and uncluttered.

Do not use excessive decorative shapes, unrelated stock imagery, or oversized design elements that reduce professionalism.

### 8.3 Heading hierarchy
Use proper document styles rather than manually formatting every heading.

Recommended hierarchy:
- Heading 1: Major chapters.
- Heading 2: Main sections.
- Heading 3: Subsections.
- Heading 4: Detailed subtopics, when necessary.
- Normal: Body paragraphs.

Maintain:
- Consistent heading sizes.
- Consistent heading colors.
- Predictable spacing above and below headings.
- Logical numbering.
- Clear distinctions between chapters and subsections.

Avoid orphaned headings at the bottom of pages.

### 8.4 Paragraph formatting
- Use left-aligned body text by default.
- Use justified alignment only where it remains comfortably readable and does not create excessive gaps.
- Use a consistent body font size, normally around 10.5–11.5 pt.
- Use approximately 1.15–1.25 line spacing.
- Apply consistent paragraph spacing, typically 5–8 pt after paragraphs.
- Use first-line indentation only where appropriate.
- Break long text into meaningful paragraphs.
- Use bullets and numbered lists where they improve comprehension.
- Avoid excessive bolding, underlining, italics, and all-caps text.

### 8.5 Whitespace and section separation
Pay particular attention to spacing between sections.

- Maintain clear separation between the end of one section and the next heading.
- Use consistent spacing before and after headings.
- Avoid placing headings directly against the preceding paragraph.
- Avoid excessive blank pages and large accidental gaps.
- Use paragraph pagination settings, page breaks, and section breaks appropriately.
- Keep related content visually grouped.
- Separate major chapters clearly.
- Avoid inserting manual blank paragraphs repeatedly to force alignment.
- Use consistent spacing rules instead of inconsistent manual formatting.

The result must feel spacious and structured without wasting pages.

### 8.6 Headers and footers
Use professional headers and footers on content pages where appropriate.

Possible elements:
- Small company logo.
- Short document title.
- Chapter name.
- Page number.
- Confidentiality classification, only if approved.

Do not overcrowd the header or footer.

Keep the cover page free of unnecessary repeating elements. Use different first-page headers and footers when appropriate.

### 8.7 Page numbering
- Use automatic page numbering.
- Use a consistent position and style.
- Keep the cover page unnumbered or visually separate where appropriate.
- Configure front matter numbering consistently if Roman numerals are used.
- Ensure the main content page numbering is correct.
- Update the table of contents and all page references after final pagination.

### 8.8 Tables
- Use consistent table widths.
- Use clear header rows.
- Apply brand colors subtly to table headers.
- Use consistent cell padding.
- Align text and numbers appropriately.
- Avoid cramped text and excessively narrow columns.
- Prevent rows from splitting across pages when inappropriate.
- Repeat table header rows across pages where supported.
- Keep tables within the page margins.
- Use landscape orientation only when genuinely necessary.

### 8.9 Callouts and important notes
When appropriate, use restrained visual treatments for:
- Important information.
- Notes.
- Warnings.
- Definitions.
- Process outcomes.

Do not turn every paragraph into a colored card. Preserve a clear visual hierarchy.
